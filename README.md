# ComfyUI-YuanCut

在 ComfyUI 里直接使用 YuanCut 视频编辑器：一个纯前端、本地优先的剪辑器，
界面由打包进插件的静态前端提供，不需要 Node 进程、数据库或上传素材。

集成方式：**静态前端 + ComfyUI 自带 aiohttp 托管 + 节点/顶栏入口 + iframe 弹层**。

- 打开即进入 **所有项目**，点项目才进入编辑器
- 素材与项目都存在浏览器 IndexedDB（与 ComfyUI 同源），不上传
- 一个 `YuanCut` 节点 + 顶栏 `YuanCut` 按钮，双击节点或右键菜单也能打开
- 关闭弹层后 iframe 常驻内存，再次打开秒开，编辑状态不丢
- 界面固定中文（内置编辑器直接以 zh 打开，插件按钮/提示/说明均为中文）

![YuanCut 在 ComfyUI 里的弹层](docs/preview.jpg)

## 安装

```bash
cd ComfyUI/custom_nodes
git clone <this-repo> ComfyUI-YuanCut      # 或者直接把目录复制/软链进来
```

重启 ComfyUI，刷新前端页面即可。`yuancut-ui/` 已随仓库提供，开箱即用。

## 使用

三种入口，效果相同：

1. 新建节点 → 分类 **YuanCut** → **YuanCut 视频编辑器**，点节点里的「打开 YuanCut」
2. 双击该节点，或右键节点 →「打开 YuanCut 编辑器」
3. ComfyUI 顶栏的 **YuanCut** 按钮

打开后直接落在 **所有项目**，点某个项目才进入编辑器。
弹层右上角还有：**项目**（回到项目列表）、**重新加载**（重载当前页）、**新标签页**、**关闭**。
也可以直接访问 `http://<comfyui>:8188/yuancut/`（自动落到项目列表）或 `/yuancut/zh/editor/`。

## 重建 yuancut-ui/

`yuancut-ui/` 是前端 `apps/web` 的静态导出产物。升级上游源码后重新生成：

```bash
tools/build_ui.sh /path/to/webapp-source
```

脚本会：复制源码到临时目录（**不会改动你的仓库**）→ 应用 `tools/patch_webapp.py`
→ `pnpm install` → `next build`（`output: "export"`）→ 把 `out/` 同步到 `yuancut-ui/`。
需要 `pnpm`、`python3`、`rsync`，首次安装依赖约 1.3 GB。

### 静态化都改了什么

| 改动 | 原因 |
| --- | --- |
| `output: "export"` + `basePath: "/yuancut"` + `trailingSlash` | 交给 ComfyUI 托管，资源不与 `/_next` 冲突 |
| 编辑器路由从 `/editor/<uuid>` 改为 `/editor?project=<uuid>` | 静态导出无法预渲染任意 uuid 的动态路由 |
| 删除 `src/app/api/**`、`middleware.ts` | 静态站点没有服务端 |
| 删除 `lib/auth`、`lib/db`、`lib/r2`、`lib/rate-limit` | 只被已删除的 API 使用，且与新版依赖类型不兼容 |
| 移除 `botid` 与统计脚本 | 纯本地插件不引外链 |
| 公开资源改用 `withBasePath()`，logo 目录改为 `logos/yuancut` | 资源要走 `/yuancut` 前缀 |
| `next/image` 关闭优化 | 静态导出没有图片优化服务 |
| 删除首页与营销页（`/[locale]/page.tsx`、privacy、terms、roadmap、why-not-capcut、playground）及其 `landing`/`header`/`footer` 组件、`public/preview` 素材 | 入口直接是「所有项目」，静态包里不再需要官网页面 |
| 构建后清理 `locales/`、`preview/`，图标只保留 manifest 引用的 192/512，删除未引用的历史图标与 `logos/others` | 运行时不会请求这些文件，纯减体积 |
| 品牌词与 manifest/locales/页面标题统一替换为 **YuanCut** | 插件内不再出现旧名字 |

## 已知限制

静态版只保留**编辑器本身**。依赖服务端的入口在构建时已处理：

- Freesound 音效搜索（`/api/sounds/*`）的标签页已隐藏
- AI 代理 / 文生图 / 文生视频（`/api/ai/*`）、参考图上传（`/api/upload/*`）、
  文本转语音（`/api/tts/*`）、账号登录：按钮仍在，但请求会 404，需要服务端才能用
- 反馈入口（顶栏按钮、移动端菜单、页脚链接）与相关组件/服务已整体删除
- 界面语言只保留中文和英文，其它语言的翻译包已从构建中移除
- 官网页面（首页、隐私、条款、路线图、why-not-capcut、playground）已从构建中移除，
  只保留编辑器、项目列表和角色页

时间线、预览、字幕、素材导入、本地导出（FFmpeg.wasm / mediabunny）等纯前端能力不受影响。
项目保存在浏览器 IndexedDB：换浏览器或清站点数据会看不到旧项目。

服务端的渲染 / 人声美化任务表会在**终态后 30 分钟**自动回收（内存 + 临时目录），
超过这个时间再来取结果会拿到「任务不存在」。

## 轨道结构

新项目默认三条轨道（上 → 下）：

1. **文字 / 特效**：只能放文字（贴纸等叠加轨道同属这一层）
2. **主视频**（主轨）：只能放视频/图片与转场，位置固定
3. **音频**：只能放音频与音效

追加与排序规则（每次写入都会统一整理，不会穿插）：

- 新视频轨道 → 主视频轨道正上方（副视频轨道紧贴主轨，文字轨道仍在最上层）
- 新文字 / 贴纸轨道 → 最上层
- 新音频轨道 → 最下层
- 三条基础轨道（文字、主视频、音频）**不可删除**，删到只剩一条也不会发生
- 旧项目打开时会自动补齐缺失的基础轨道（例如只有主轨的项目会补上文字轨与音频轨）

## 预览：原生播放 + DOM 悬浮层（不再每帧合成 canvas）

上游的预览是「实时合成」：每个 rAF 把 1080p 视频帧 `drawImage` 进 canvas，
字幕、贴纸、转场都画在同一张画布上。这里改成了「播放器照常播放，字幕浮在上面」：

- 视频 = 原生 `<video muted playsInline>`，浏览器自己解码播放；JS 只做**对表**
  （跑偏超过 0.35 s 才 `currentTime` 校正，暂停/拖播放头时立即 seek），不逐帧搬图
- 图片/贴纸 = `<img>`（贴纸走 iconify SVG），位置用和 `VisualNode.renderVisual` 同一套算法：
  contain 缩放 × `transform.scale`，再按 `displaySize / canvasSize` 换算成屏幕像素
- 字幕 = 一张**静态** `1920×1080` 画布，仍用原来的 `TextNode` 画（像素与旧预览一致），
  只有字幕内容/样式/出现时间变了才重画；没有字幕时这张画布根本不存在
- 播放中 React 不逐帧重渲染：只有「可见元素集合变化」或暂停时拖播放头才更新一次
- **时钟以视频为准**：上游的播放时钟是 `requestAnimationFrame` 推的，浏览器一限流 rAF
  （窗口被遮挡、后台标签页、机器忙）时钟就冻住，而原生 `<video>` 照常在播 → 会看到
  「视频在动、字幕卡住不动，一暂停字幕才出来」。这里字幕/贴纸的可见性改为按
  `video.currentTime` 换算回时间线时间，由 150ms 定时器 + `timeupdate`/`seek`/`play`/
  `pause` 事件驱动；播放/暂停也由该通道同步给 `<video>`，整套不再依赖 rAF
- 结果：播放 1 条 1080p 片段时 GPU 利用率从 8–67%（尖峰 63/67）降到 7–18%（多数 ~10），
  `drawImage` 调用数 0 次/秒（原来约 30 次/秒 × 1920×1080）
- 导出仍是服务端 ffmpeg（`yuancut_render.py`），「导出当前帧」/AI 取帧仍在用那套 canvas 渲染
- 已知差异：转场（`TransitionNode`）在预览里不做混合（导出本来也不支持）；
  「背景模糊」里视频用的是封面图做模糊底，图片直接用原图

## 音频导出 / 合并

- 选中音频片段后 **右键 →「导出音频」**：导出为 WAV
  - 单段：直接导出，不加编号
  - 多段：按时间轴从左到右分别导出，文件名自动编号 `01_…`、`02_…`
- 选中多段音频后 **右键 →「合并选中的音频」**：合并成一段整体音频
  - 只支持同一条音频轨道上的片段；保留相对位置与中间的空隙
  - 合并结果是新的音频素材（`合并音频`），之后导出就是一个完整文件
- 音频同样可以用「拆分」剪开，再合并回去

## 人声美化（去混响 / 去喷麦 / 降噪 / 提升清晰度）

选中**带声音的片段**（音频片段，或带音轨的视频片段）→ 右侧属性面板「人声美化」→
**勾选「启用」**，拉强度 → 点处理。勾选即处理，取消勾选立刻回到原声，滑块未勾选时是灰的、不可拖。
- 点一下勾就**立刻打上**（本地乐观状态，不等处理完，处理失败才回落），下面换成进度条 +
  「准备中… → 解码音频 x% → 神经网络增强 x% → 处理完成」，处理完再把状态交回片段字段
- 视频片段只换声音、不换画面：处理结果挂在 `voiceBeautifyMediaId` 上，画面仍来自原视频，
  预览（`collectAudioClips`）和导出（导出请求里把画面那条置 `muted`、另加一条处理后音频）用的是同一个 wav
- 分离过音频（`muted`）或本来就没有音轨的视频不显示这个开关（音频探测只看封装、不解码，几毫秒，按素材缓存）
- 一次处理生成新素材 `<原名>-人声美化.wav`；取消勾选只是切回原素材，处理结果一直留着，再勾选立刻生效
- 处理流程：MossFormer2_SE_48K（48 kHz 语音增强，CPU 推理 ≈ 0.12 倍实时）
  → DSP 增强链（80 Hz 高通 / 250 Hz 去浑浊 / 3 kHz 存在感 / 4.5–8 kHz 去齿音 / 软门限 / 压缩 / 限制）
  → 按「强度」与原声干湿混合 → 整段响度归一到语音 −20 dBFS、峰值 ≤ −1 dBFS
- 与**变速（Sonic 变速不变调）可以叠加**：美化后的素材同样按时间线倍速渲染，
  播放器对每块 PCM 做「身份 + 速率」校验（换了素材/改了速度就丢弃在飞的旧块），
  输出再做一遍软限幅，避免峰值越界硬削波（听起来就是破音）
- 时长与原素材严格一致，位置/裁剪/变速都不用改
- 改强度重做：拖动强度后出现「按新强度重新处理」，原始素材一直留着（`voiceBeautifySourceId`）

运行环境（只装一次，**独立 venv**，不影响 ComfyUI 主环境）：

```bash
tools/voice/setup_env.sh
```

会建 `~/.local/share/yuancut/voice/venv`（torch CPU + clearvoice）并从 ModelScope 拉
`MossFormer2_SE_48K` 权重（约 211 MB）。设置 `YUANCUT_VOICE_ROOT` 可换目录。

内存与安全：音频按 20 秒分块、重叠 1 秒交叉淡化流式处理，**内存占用与素材长度无关**
（实测 4 分钟素材峰值约 0.9 GB）；worker 自身还加了 6 GB 地址空间上限，并尽量通过
`systemd-run --user --scope` 跑在独立 cgroup 里——即使它失控，也只会杀它自己，
不会再连带把 ComfyUI 一起 OOM 掉。

## 裁剪 / 拆分：每段都是「完整素材的副本」

拆一段视频不会再把它锁死在原范围内：拆完的每一段都指向同一条素材，
`trimStart` / `trimEnd` 只是「这扇窗口在素材里的位置」，所以每段都能再往两头拉。

- 例：素材 15 s，轴上一段 15 s → 在 5 s、9 s 处拆分 → 得到 5 / 4 / 6 s 三段；
  三段在时间轴上首尾相接（0–5、5–9、9–15），画面内容连续
- 想加长第一段：拖它的右边缘，可以一直拖到素材结尾（`duration` 变大、`trimEnd` 变小），
  后面两段自动顺延，仍然首尾相接；缩短同理
- 伸缩上限取**素材真实长度**（`asset.duration`），不是「这段原本留了多少」，
  所以任何一段都能扩到整条素材
- 左边缘往左拖不会再出现「起点被钉在 0 但内容整体右移」的错位：
  时间线不允许负起点，扩不下就不动（`trimStart` 与 `startTime` 一起夹住）
- 变速不影响这套语义：`duration × playbackRate` 才是吃掉的素材长度

## 拖拽与体积碰撞

**视频轨没有碰撞**：片段可以自由拖动、自由拉伸，重叠也不管（主轨就是一张自由画布）。

**音频 / 字幕 / 贴纸轨有体积碰撞**（`lib/timeline/collision.ts`）：

- 拖动：往邻居身上拖会被挡住 —— 落在 `[左邻居结束点, 右邻居开始点 − 自身时长]` 之间，
  拖过头就贴在邻居边上，不会盖住别人（`use-element-interaction.ts` 在拖动过程中和落点各夹一次）
- 拉伸：右边缘长到右侧邻居的开始点为止，左边缘退到左侧邻居的结束点为止（`use-element-resize.ts`）。
  文字/字幕走的是「可无限延长」那条分支（`canExtendElementDuration` 对 text/image 为 true），
  这条分支也加了同样的邻居夹紧 —— 否则字幕能直接把邻居盖掉（以前只有音频会被挡住）
- 判定用元素**当前**位置算左右邻居，所以拖动跨越邻居时边界不会错乱

**选中片段时，它两侧的「添加转场」加号会让位**：那个 24 px 的加号正好压在两段之间的接缝上，
会把右边缘的缩放手柄和拖拽区盖住。现在只要接缝两端的任一元素被选中，这个接缝就不渲染加号；
取消选中就回来，其它接缝的加号不受影响。

**播放头吸附**（`lib/timeline/playhead-snapping.ts`）：拖动/点击播放头时，靠近任何片段的
裁剪点（起点或终点）会被吸过去，进吸附阈值 8 px，已吸附后再挪 14 px 才脱开（迟滞），
所以能明显感觉到「被吸住一下」，但稍远处又是自由拖动。

## 多选与集体操作

时间轴上**框选**（在空白处拖出选框）可以一次选中任意轨道的多个片段，选中的片段：

- **一起拖动**：拖其中任意一个，整组跟着走（上游 `moveElementsByDelta`）
- **一起在属性面板改**：面板顶部出现「已选 N 个片段：下面的修改会一起应用」，
  数值取第一个选中片段，改动分发到整组：视频/图片（位置、缩放、旋转、透明度、速度、人声美化）、
  音频（音量、速度、人声美化）、字幕/文字（字号、颜色、样式、变换）、贴纸（变换、透明度、颜色）
- **一起改速度**：每个片段按**自己**的当前速度换算时长（`duration * 旧速度 / 新速度`），
  所以 1x、2x 混选后一起调到 1.5x，时长各自按比例缩，不会出现某个片段时长算错
- **一起人声美化**：按**素材**去重 —— 多个片段指向同一个素材只跑一次服务端任务，
  处理完把同一个结果回填给这些片段；不同素材逐个处理，进度条显示「第 2/3 个素材 · 增强 40%」

### 框选之后快捷键失灵（已修）

上游 `use-keybindings.ts` 的规则是「文档里只要有选中的文字就跳过所有快捷键」。
时间轴框选、拖动片段都会在文档里留下一个文本选区，于是框选完按 Delete 经常没反应
（有时又正常 —— 取决于上一次点击有没有清掉那个选区）。

现在：

- 判定改成「选区是否落在 `input` / `textarea` / `contenteditable` 里」，浮在页面上的选区不再吞快捷键
- 框选按下时清掉残留选区，拖动期间 `selectstart` 直接 `preventDefault`，松开再清一次

实测：框选 3 段 → `window.getSelection()` 长度 0 → Delete 删掉 3 段；
故意先选中整页文字（221 字符）再按 Delete 也能删；焦点在输入框里按 Delete 仍然只删文字、不动片段。

### 多个片段变速时「破音 / 变无声」（已修）

两个独立的原因，都在 Sonic 变速这条链上：

1. **播放器 worklet 的状态写在模块作用域**（`sonic-player-source.ts` 里的 `fifo` / `playing` / `startAt`）。
   AudioWorklet 的模块脚本在一个全局作用域里只求值一次，模块级变量由**同一个处理器的所有实例共享** ——
   每个片段各开一个播放器时，它们抢同一个 FIFO：谁先跑到 `process` 谁把 PCM 读走，其余只输出静音。
   实测（3 段 1.5x / 0.5x / 2x，RMS 每 0.5 s 采样）：修之前只有最后一段有声，前 16 s 全是 0；
   改成实例字段后 0–18 s 连续 0.0108~0.0111，无静音采样。
2. **每次时间轴变化都清空解码缓存**（`handleTimelineChange` 里的 `decodedBuffers.clear()`）。
   改一个片段的速度就会把整条素材重新解码一遍，几百秒的 mp4 要 1~3 秒，那段时间就是掉音；
   几个片段挨个改，听感就是「先破音、然后彻底没声」。
   现在缓存按**素材文件对象**判定新鲜度（素材没换就不重解码），只保留最近 24 个素材。
   实测：播放中连续改 3 个片段的速度，最长连续静音 **0 ms**，峰值 0.016 无削波。

顺带把播放器 worklet 改成**每个 AudioContext 只注册一次**，并回收时间轴上已删除片段的播放器。

## 相邻片段之间的缝

同一条轨道上**首尾相接**的两段之间画一条 2 px 深色缝（`borderRight`，走 border-box，
不吃时间）：内容上是连着播的，但时间轴上边界一眼能看出来。不相邻的片段没有这条缝。

## 视频片段的三段式显示

视频轨道上的片段按高度分成三段（`timeline-element.tsx`）：

1. 上 ¼：片段名称（左）+ 时长（右）
2. 中 ½：素材画面（原有缩略图条，缩略图高度自动跟着变小）
3. 下 ¼：该素材的音频波形，**复用音频轨道那套 `AudioWaveform`**（wavesurfer，颜色/粗细/加载态一致），
   渲染高度按 2 倍给、容器 `overflow-hidden` 只留上面一半 → **只看上半边波形**；
   勾了人声美化就画处理后的音频（跟你听到的一致）；**分离音频 / 静音后不画波形**，只留一个「静音」小标

特意没有另写一套波形绘制：视频文件用 `AudioWaveform` 的 `audioBlob` 通道解码即可
（实测 Chromium 能直接 `decodeAudioData` 解 mp4/AAC 音轨），代码量与维护成本都最小；
素材没音轨时该条显示「音频不可用」，不会报错。

波形显示：视频片段底部 1/4 与音频轨道一样复用 `AudioWaveform`（wavesurfer），
按 2 倍高度渲染、容器裁掉下半 → 只看上半边。颜色、粗细、加载态与音频轨道一致。

> 参考剪映的实现（`mammon::WaveformVisualizer::getPoints()` + `%PeAKs` 峰值缓存 +
> Qt 场景图 `QSGGeometryNode`）做过「峰值缓存 + 整层 canvas」版本，因观感与 GPU 占用都不理想已回退。





## 时间轴刻度

- 默认缩放开在 **5 秒一格**（30 px/秒，标签间距 150 px），格内保留 1 秒细刻度
- 放大 / 缩小会按像素间距自动切换刻度：帧级 → 1 秒 → 3 秒 → 5 秒 → 10 秒 → 30 秒…
- 空时间轴或很短的工程也能缩到约 30 秒的可视范围（原来会被“适应宽度”卡在过细的刻度上）

## 语音转字幕

字幕转录只有一个方法：**插件内置的 MOSS-Transcribe-Diarize 模型**（原来的 Whisper
Small / Large v3 Turbo / Distil Small 三个浏览器模型已全部删除）。

- 前端只做音频准备：把片段解码成 16 kHz 单声道 Float32，每 5 分钟一块 POST 到
  `/yuancut/transcribe`，再把返回的句段画成字幕
- 后端（`yuancut_transcribe.py`）在本机调用 MOSS 推理，一次拿到「说话人 + 起止时间 + 文本」，
  不需要浏览器下载权重，也不依赖 WebGPU/WASM
- **引擎和权重下载器都内置在本插件里**（`yuancut_asr/moss_engine.py`、`yuancut_asr/moss_download.py`），
  不再需要 `custom_nodes/ComfyUI-Moss-Diarize-Yuan` 这类外部节点包，删掉它也不影响转写
- 权重放在 **`ComfyUI/models/Yuan_Cut/MOSS-Transcribe-Diarize/`**（约 1.8 GB）。
  **检测不到就自动下载**：ModelScope 国内源优先，失败回退 HuggingFace（huggingface.co → hf-mirror.com），
  逐文件断点续传，下完做字节数校验；ComfyUI 启动时就在后台开始下，不阻塞启动
- 第一次点「开始转写」时如果权重还在下，面板会显示「模型下载中 12%（0.21/1.83 GiB）」，
  下完自动接着转写；控制台同时每 5 秒打印一次进度
- 环境变量：`YUANCUT_MOSS_AUTODOWNLOAD=0` 关闭启动时自动下载、
  `YUANCUT_MOSS_MODEL_DIR=/abs/path` 换权重目录、
  `YUANCUT_MOSS_DOWNLOAD_SOURCE=modelscope|huggingface` 指定下载源
- `GET /yuancut/transcribe` 返回引擎与下载状态（`model_ready` / `downloading` /
  `download_progress` / `missing_files` / `download_error`），便于排查
- 模型首次转写时载入并常驻显存（BF16 + SDPA），之后重复转写不再重新加载
- 单次请求上限 5 分钟音频，长素材由前端自动分块并拼接时间轴；后端最多接受 1 小时
- 改了 `yuancut_transcribe.py` / `yuancut_asr/` 或新增路由后需要重启 ComfyUI；
  只换前端静态文件不用重启

实测（RTX 3090，8 秒中文素材）：模型加载 2.0 s，转写 5.6 s，返回
`[S01] 0.00–6.14 s` 一条带说话人的句段。

字幕断句（中文/日文）：上游按空格分词，中文没有空格会把整段变成一条超长字幕，
所以补了一套按字切分（`lib/transcription/caption-text.ts`）：

- 断句后用 ICU 词典（`Intl.Segmenter`）分词、**按词装箱**，不会把「人工智能」拆成「人工｜智能」
- 按 `。！？；，、：…` 断句，**这些标点不进入字幕文本**
- 断点优先落在自然位置：助词后（的/了/啊）、连接词前（然后/所以/我们…），并避开「单字结尾」「助词开头」
- 单条上限 16 字，但行长贴近理想值（约 12 字），不硬顶满行；1~2 字的碎句并回上一条
- 中文里夹英文（`这个是 Python 代码`）时，**空格不是断点**，英文单词也不会被拆开，行首行尾不留空格
- 数字/时间里的标点不算句末：`1.0`、`10:30`、`3,000` 不会被切开
- 每条时长按「字数 ÷ 该段语速」分配，首尾相接不留空档
- 英文等有空格的语言仍走上游按词切分，行为不变

## 音频标签（音效 / 提取音频）

左侧面板在「媒体」和「文字」之间多了一个 **音频** 标签，样式与「媒体」一致
（同一套卡片网格、图标按钮、拖拽与滚动条），离线可用，不需要任何服务端接口：
- 卡片和「媒体」面板是**同一套组件**：直接复用 `media.tsx` 里的 `GridView` + `MediaPreview`
  （同一份缩略图/占位图、时长角标、右键菜单、拖拽与选中样式），音频面板不再各写一套
- **添加音频 / 音效**：左上角音乐图标按钮，选本地音频文件（`audio/*`），
  走与「媒体」相同的导入管线，导入后以同样的卡片出现在音频面板
- **从视频提取音频**：左上角摄影机图标按钮，选本地视频文件（`video/*`），
  用 mediabunny 抽出音轨，转成 `原名.wav` 存进音频面板（不转码整个视频，只取音频轨）
- **播放与媒体一致**：点卡片 = 选中，右侧**播放框**用同一个播放器播放，带原生进度条；
  再点一次取消选中。拖动进度条、暂停/继续都在播放框里完成
- 面板也支持把音频/视频直接拖进来：音频按普通素材导入，视频自动走提取流程
- 卡片可以拖到时间轴，也可点「＋」按播放头插入；拖拽素材到时间轴时与「媒体」行为一致
- 全部在浏览器本地完成，文件不上传；提取失败会逐个文件提示，不影响其它文件

### 媒体与音频是两套独立的素材库

- 素材带一个归属标记（`panel`）：`media` 属于媒体面板，`audio` 属于音频面板
- **媒体面板只显示 media**：即使往媒体里拖音频，它也只留在媒体里，不会出现在音频面板
- **音频面板只显示 audio**：音频面板导入或提取的素材，也不会跑到媒体面板
- 归属标记随素材一起存进 IndexedDB/OPFS，刷新或重开项目都保持分开
- 本次升级前已存在的素材没有归属标记，按 `media` 处理（会显示在媒体面板）；
  需要出现在音频面板的旧音频，重新导入一次即可

## 字幕导入 / 导出

两个方向用同一套格式，**互相可以对上**：

| 格式 | 导出 | 导入 |
|---|---|---|
| **SRT** | 按时间线上的文字元素生成 `序号 / 时间码 / 文本` | 识别时间码，**按字幕文件里的时间**落轨（以播放头为 0 点），每条时长取自文件 |
| **TXT** | 一行一条，不带时间码 | 按非空行数逐条落轨，每条时长用当前字幕模板的默认时长 |

导入入口在「字幕」面板的 **Import** 页：

- **选文件**：`导入 .srt / .txt 文件` 按钮（接受 `.srt` / `.txt`），内容会先读进文本框，方便确认和改字
- **粘贴**：直接把 SRT 全文或纯文本粘进文本框，点导入即可；格式自动识别，不需要手动选
- 两种方式都从**播放头**开始落轨，SRT 会保留条与条之间的相对时间差
- 面板上的条数统计对 SRT 按「字幕条数」算（不会把序号、时间码算进去），纯文本按非空行算

导出在导出面板勾选「字幕导出」，格式选 `SRT` 或 `TXT`；导出的 SRT 时间码修掉了 `,1000`
这种越界毫秒（先四舍五入到毫秒再拆分），再导入时能原样还原。

## 素材框选与删除

- 「媒体」和「音频」面板都支持**框选**：在空白处按住左键拖出选框，与选框相交的素材会被选中，
  卡片显示选中描边；面板**右下角**显示「已选 N 项」
- **只有一套右键菜单**（面板级），右键任意位置弹的都是它，菜单内容：删除 / 导出所选 / 取消选择；
  三者都作用于**当前选中集合**，与右键点在哪张素材上无关
- 右键一个还没被选中的素材时，会先把它并入选中；已经在选中集合里（框选多条）就保持整个多选不动
- **左键选中也会进选中集合**：点一张卡片等于单选它，此时右键菜单的「删除 / 导出所选」和
  键盘 **Delete / Backspace** 都直接作用于这一条；再点一次卡片取消选中
- 选中后按键盘 **Delete / Backspace** 删除（监听在捕获阶段，不会被时间轴的快捷键吞掉）
- 实现上，动作发生时直接读选中集合（`getState()`），不再用渲染时的快照，
  所以框选后立刻右键也一定是删全部
- 面板上不再有常驻的操作栏/按钮，选中数量只在右下角的小角标里显示
- 点击空白处或切到别的标签页会清空选中，不会残留在别的面板
- **删除素材不会破坏时间线**：时间轴上的片段保留原位置、时长和轨道，
  只是标红显示「素材丢失」，方便你重新导入同名素材或自行调整
- 素材丢失时的表现：预览不再渲染该片段（不会黑屏或报错），音频播放自动跳过该段，
  导出的成片同样保持时间线节奏不变

## 性能说明（进入 / 退出项目）

- **预取**：插件返回项目列表 HTML 时注入 `<link rel="prefetch">`，把编辑器要用的
  JS/CSS（约 3 MB）提前拉进浏览器缓存，第一次进入项目也不用现下载
- **不整页重载**：弹层顶栏的「项目」改为 `postMessage` + 前端路由跳转
  （前端 `components/providers/host-bridge.tsx`），不再重载整个 iframe
- **素材并发**：项目素材从 IndexedDB 读取改为 4 路并发（原来是逐个串行），
  素材多的项目进入明显更快
- **加载提示**：首次打开或「重新加载」时显示「正在加载 YuanCut…」，
  延迟 150 ms 出现，避免快速加载时闪烁
- **退出项目不再等缩略图**：视频项目直接跳过（改在下次进入时后台生成），
  其它项目最多等 200 ms；空项目（时长 0）立即返回

本地实测（缓存命中、localhost）：打开面板 ≈40 ms、进入项目 ≈40 ms、
站内「项目」跳转 ≈30 ms、退出项目 ≈50–80 ms，无长任务（long task）。
首次冷启动受机器磁盘/ComfyUI 自身负载影响，会看到加载提示。
